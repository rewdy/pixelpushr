# Operating pixelpushr

## Local browser-window walkthrough

Install Bun 1.3+ and Docker, then follow the [local development commands](../README.md). Copy `apps/api/.env.example` to `apps/api/.env`, run the database migration and Floci bucket initialization, and start `bun run dev`. Open `http://127.0.0.1:5173` in a desktop browser. Register the first account (email confirmation is required with Cognito, but not local auth), then create the single organization. This first account becomes the owner. Open **People & access** to invite another administrator; in local development, retrieve the invitation in Mailpit at `http://127.0.0.1:8025`.

Upload an image or video on **Media**, then create or open a playlist on **Playlists**. Choose **Add media** to open the searchable thumbnail panel (a drawer on smaller screens); each **+** appends a new draft item, including when that asset is already in the playlist. Use item checkboxes to delete several items or apply one duration to selected images and repeat-for-duration videos; **Deselect all** clears the checkboxes without changing the draft. Play-once videos are not changed by bulk duration. Images use a duration; videos can play once or repeat for a duration. Reorder with the arrow buttons. All these edits remain local until **Save playlist**. **Show preview** plays the current unsaved draft in a compact loop; it is not a synchronized view of any running display and does not publish edits.

Register a display on **Displays**, assign one or more always-active playlists, copy its public URL, and open that URL in a separate browser window. The player needs no sign-in and starts automatically. Use `d` on the player keyboard to reveal a minimal online/offline diagnostic badge. A heartbeat updates the display's last-seen timestamp in the console.

## Scheduling and override semantics

Always-active playlists appear first in the normal queue, in their configured order. All currently active additive schedules follow in schedule position order. Their items cycle as one combined queue. Normal manifest changes wait until the existing queue finishes; an empty player starts a newly assigned queue immediately. The player polls every 15 seconds by default. A new schedule may therefore be observed up to one polling interval after its boundary, then begins at queue rollover.

Schedule entry uses local date and time in the organization's IANA timezone. One-time windows include their start and exclude their end. Weekly windows repeat every _N_ calendar weeks, keeping the entered wall-clock time across daylight-saving changes. For three campaigns that rotate one per week, make three seven-day windows starting on consecutive weeks, each with **Repeat every 3 weeks**. The first always-on branding playlist remains active alongside each campaign. The **Preview effective queue** control shows the normal queue for a chosen local time. Changing the organization timezone preserves each recurring window's entered wall-clock date/time in the new zone; one-time windows remain fixed absolute instants. Ambiguous fall-back times use Temporal's default earlier-offset interpretation, and nonexistent spring-forward times shift forward.

An override has an explicit start, expiration, and priority. While active, only the highest-priority override playlist plays; ties resolve deterministically by assignment ID. Start, end, and winner changes interrupt the current item immediately. **Activate now** uses the server's current time as the start, but still requires an explicit expiration. The next player manifest activates it. The manifest carries absolute transitions and server time so the browser can compensate for clock drift. Clock synchronization on the player device is still recommended.

Within a stable normal or override queue, the public player crossfades to the next item over the final 500 ms of an image or repeat-for-duration video's configured time. This overlap counts within that duration, so a 10-second item still advances at 10 seconds; repeat-video loops inside its duration do not trigger a fade. A play-once video fades during its final 500 ms when its remaining time is known. If duration is unavailable or the next asset cannot be prepared, the player makes a direct cut or skips the unavailable item rather than extending playback or leaving a stale overlay. Override start, expiration, and winner changes never fade: they cut at the server-adjusted effective time, including during an item fade or while offline with a cached override window.

## Media and offline behavior

Accepted MIME types are JPEG, PNG, WebP, GIF, MP4, and WebM. The API checks file signatures, upload size, and basic browser preview metadata before publishing. It does not transcode or deeply inspect video codecs. An H.264 MP4 fixture is covered by the Chromium browser tests; audio codecs have not been validated, and the player is muted. Verify other codecs on the actual playback browser and hardware. GIFs display as the browser animates them and advance at the configured image duration. Defaults are 20 MB per image and 500 MB per video, configurable through API environment variables.

After a video becomes ready, the browser attempts to capture an early frame and upload a JPEG poster through the authenticated API. The poster is limited to 1 MB. If extraction or upload fails, the video stays ready and the media library and playlist editor show a video fallback icon; older videos without posters behave the same way. To retry with the current UI, upload the video again. The API also accepts a JPEG poster for an existing ready video at `PUT /admin/media/:id/thumbnail` for a future dedicated retry control. Local development stores posters in Floci beside the original video (or in `.local-media` with local storage); Mailpit is only for invitation email. To check the full local path, start Compose and `storage:init` as in the README, upload a playable MP4, and confirm its still image appears in the Media library. A failed poster should not prevent adding that video to a playlist.

The reference player is a current desktop Chromium browser, tested with Playwright in a separate browser window. The Raspberry Pi Zero W is a future hardware target, not yet performance- or codec-validated. The player keeps the last valid manifest in local storage and prefetches normal and override media into browser Cache Storage. A failed refresh leaves current playback running; on reload during an outage, cached media can play if the browser retained it. Known override expiration still returns to the cached normal queue offline. Browser storage is best-effort and may be evicted; do not treat it as durable emergency delivery. Each item with an advertised `Content-Length` above 500 MB is skipped by the prefetcher. For deployments, test the actual kiosk browser's cache quota, autoplay behavior, network recovery, and sleep settings.

## AWS deployment

The Terraform root is `tf/`, with infrastructure in `tf/modules/platform/`. It creates two private and two public subnets across two availability zones, a single NAT gateway, private RDS PostgreSQL with an RDS-managed master secret, an HTTP API backed by Hono Lambda, S3 buckets for the SPA and media, one CloudFront distribution routing `/api/*` and `/media/*`, a Cognito user pool, SES sender identity, and CloudWatch log groups. Private Lambda access to Cognito, SES, S3, Secrets Manager, and public key discovery goes through NAT. A single NAT is economical for the MVP but is not highly available across availability zones. RDS and the NAT gateway incur ongoing charges even when idle.

Prerequisites: an AWS account with deployment credentials, an existing Route 53 hosted zone, a DNS name for the app, and an issued ACM certificate for that exact name in **us-east-1** (CloudFront's certificate region). Verify the invitation sender identity in SES and request production sending access if the account is still in the SES sandbox. The deployment does not provision these account/domain prerequisites or create external AWS resources until you explicitly run `terraform apply`.

1. Run `bun install`, `bun run build`, and `bash scripts/package-lambda.sh` at the repository root. The packaging script creates ignored `artifacts/lambda.zip` with both handlers and migrations.
2. Copy `tf/terraform.tfvars.example` to `tf/terraform.tfvars`, and fill in the region, environment, domain, Route 53 zone ID, ACM certificate ARN, and sender address. Use a separate Terraform state and non-overlapping `vpc_cidr` for each environment/region. Protect your state file and keep it out of version control; configure a remote backend before a team or production deployment.
3. Run `terraform -chdir=tf init`, `terraform -chdir=tf validate`, `terraform -chdir=tf plan`, and review the plan. Then run `terraform -chdir=tf apply` only when you intend to provision resources.
4. Apply database migrations before first use: `aws lambda invoke --region YOUR_REGION --function-name "$(terraform -chdir=tf output -raw migration_lambda_name)" /tmp/pixelpushr-migration-result.json`, then inspect that response and the migration Lambda logs for `{ "migrated": true }`. Re-run this migration function after every release that adds a migration.
5. Upload the built SPA: `aws s3 sync apps/web/dist "s3://$(terraform -chdir=tf output -raw web_bucket)" --delete`. `--delete` only removes stale build files from this exact web bucket; do not use it with the media bucket. Invalidate the CloudFront HTML entry (or wait for its 60-second cache TTL) before testing the new release. The `/assets/` build files are content-hashed.
6. Check `$(terraform -chdir=tf output -raw api_health_url)` for HTTP 200. Open the web URL output, confirm the owner account, create the organization, invite an admin, and walk through the browser-window display test above.

The Lambda handlers obtain the RDS-managed password from Secrets Manager at cold start. Startup fails clearly if required configuration is missing. `/api/health` returns HTTP 503 if PostgreSQL is unavailable. Request and dependency failures are logged as structured JSON in CloudWatch. API responses are not cached by CloudFront; media is cached for up to a day. The public player URL contains a random display token. Player access control and private media delivery are intentionally out of scope for this MVP; do not upload sensitive material.
